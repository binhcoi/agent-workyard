# R0/M1 acceptance record

Status: complete, with no M1 blockers. Managed worker execution starts with M2.
This record describes implementation evidence without reproducing the private
planning sources.

| M1 gate | Implementation and check |
| --- | --- |
| Foundation has clear component boundaries | Go packages separate core vocabulary, worker adapter contract, supervisor control contract, configuration, CLI, and the reserved Codex adapter. All compile together. |
| Logical workers and runtime capabilities remain harness-neutral | Contracts distinguish worker, conversation, runtime, resources, task attempts, acceptance, delivery confirmation, cancellation confirmation, and unknown telemetry. No Codex-specific type appears in core or coordinator contracts. |
| Reusable initial configuration exists | Supervisor, general worker, implementer, reviewer, plus planning, handoff, and verification skills are in a standalone bundle. |
| Another repository can load configuration | Automated CLI and loader tests use separate temporary project roots, load the shared bundle, render all profiles and selected skills, and confirm existing instructions are unchanged. |
| Project-specific configuration is additive | Loader tests exercise project common and per-profile additions, optional configuration, visible invalid references, and no writes. |
| Work stays within M1 | No worker process, state store, scheduler, installer, or second adapter implementation. CLI exposes only configuration operations. |

## Verification

an official toolchain was downloaded to a temporary directory and its SHA-256
checked against the official release metadata. No system installation was changed.

Output contained selected skills and project additions; SHA-256 hashes of all three project input files were identical before and after. No sample application was copied. |

The initial test run exposed incorrect handling of a wrapped missing-file error
for an optional project config. The failure was reproduced through the built CLI,
fixed using an unwrapping error check, and verified through both tests and the
same real CLI path.

Real Codex worker execution, model inference, enforcement, recovery, and Windows
runtime behavior are outside the verified M1 configuration path. Cross-compilation
cannot establish Windows runtime correctness. No commits were created.
